## 1. 개요 및 개발 원칙

본 문서는 `PRD.md`에 명세된 **AI 보안 로그 분석기**의 요구사항을 충실히 반영하여, 단계별로 예측 가능하고 검증 가능하도록 수립된 **스프린트(Sprint) 단위 개발 계획서**입니다.

### 1.1 핵심 개발 목표
- **단일 화면 완결형 인터페이스:** 로그 입력부터 결과 확인까지 한 화면에서 직관적으로 완료
- **신속하고 정확한 분석:** 최대 100줄의 보안 로그에 대해 1분 이내에 공격 유형, 위험도, 분석 설명 제공
- **견고한 예외 처리:** 9가지 예외 상황(E-01 ~ E-09)에 대한 철저한 방어 로직 구현
- **보안 원칙 준수:** 분석 결과는 1차 참고용임을 명확히 인지하고 데이터 저장 및 불필요한 기능 배제

### 🏃 Sprint 2: AI 분석 엔진 및 분석 로직 구현

#### 🎯 목표
- PRD F-02, F-03, F-04, F-05 요구사항 충족
- 6대 공격 유형 판별, 4단계 위험도 산출, 신뢰성 있는 분석 설명 생성

#### 📋 작업 항목 (Tasks)
1. **분석 엔진 아키텍처 구축 (`lib/analyze.ts` 또는 `app/api/analyze/route.ts`)**
   - LLM API(Gemini / OpenAI 등) 연동 또는 정밀 규칙/패턴 매칭 하이브리드 엔진 구현
   - 정형화된 JSON 응답 스키마 강제:
     ```json
     {
       "attackType": "SQL Injection",
       "riskLevel": "높음",
       "description": "로그인 요청에 SQL 구문으로 판단되는 비정상적인 입력이 포함되어 있어 인증 우회 공격 가능성이 있습니다."
     }
     ```
2. **공격 유형 분류 로직 (F-03)**
   - `SQL Injection`: `' OR '1'='1`, `UNION SELECT`, `admin'--` 등 감지
   - `XSS`: `<script>`, `javascript:`, `onerror=` 등 스크립트 삽입 패턴 감지
   - `Brute Force`: 동일 IP/계정에 대한 연속 실패(401/403) 및 짧은 주기 요청 감지
   - `Path Traversal`: `../../etc/passwd`, `..\..\windows\system32` 등 상위 경로 접근 감지
   - `정상 요청`: 통상적인 HTTP 200 GET/POST API 및 정적 자원 요청
   - `판단 불가`: 로그 데이터 부족 또는 불명확한 비정상 요청
3. **위험도 평가 로직 (F-04)**
   - `치명적`: 시스템 침투, DB 탈취 등 즉각적 영향이 있는 공격
   - `높음`: 인증 우회, 주요 취약점 대상 공격 시도
   - `중간`: 무차별 대입 시도, 단순 스캐닝 등
   - `낮음`: 정상 요청 또는 경미한 이상 징후
   - `판단 불가`: 불확실한 경우 과도하게 높은 위험도를 부여하지 않고 명시
4. **분석 설명 생성기 (F-05)**
   - 보안 입문자도 쉽게 이해할 수 있는 1~2문장의 명확한 한국어 설명 생성

#### ✅ 완료 조건 (Definition of Done)
- [x] 모든 대표 공격 유형 및 정상/판단불가 케이스에 대해 정확한 분석 결과 출력
- [x] 1분 이내 빠른 응답 완료
